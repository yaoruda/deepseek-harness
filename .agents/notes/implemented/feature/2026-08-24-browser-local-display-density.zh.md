# Agent Note: 浏览器本地显示密度

Status: implemented

[English](2026-08-24-browser-local-display-density.md) | 中文

## 问题

电脑端会话尺寸在手机屏幕上占用过多纵向和横向空间。对于安装后的 iOS Web 应用，浏览器缩放并不是可靠的产品设置，而把表单控件缩小到 16 CSS 像素以下会触发 iOS 聚焦放大。

## 决策

Web 组合包含一个纯客户端显示密度插件。它负责经过校验的浏览器本地偏好，提供标准、紧凑和超紧凑值，让手机宽度视口默认使用紧凑，并把选择器提供给通用设置。该偏好不会进入 Host 设置、Session 历史或模型输入。

插件投影一个文档属性，用来选择由 ui-theme 装载的共享显示密度变量。会话和 Markdown 的归属方使用这些变量调整助手与用户文字、transcript（文本记录）节奏、用户气泡和助手表格。标准模式保留现有尺寸。所有预设中的输入框文字都保持 16 px，并且继续允许手动 viewport 缩放。

选择结果存储在一个浏览器配置中。存储失败时内存中的选择仍然可用，格式错误的持久化值会回退到基于视口的默认值。

## 考虑过的替代方案

**全局页面缩放。** CSS zoom 或限制性 viewport 缩放也会缩小触摸目标、地图、控件和聚焦几何，并干扰浏览器无障碍缩放。

**Host 支撑的显示密度设置。** 服务器持久化会把面向手机的选择同步到电脑浏览器。显示密度描述的是一个视口和浏览器配置，因此本设备存储与其范围一致。

**没有选择器的纯响应式 CSS。** 固定的媒体查询选择无法为视力需求、表格密集工作或非常规尺寸设备提供退出方式。

## 后果

手机用户可以看到更多会话和表格内容，同时不改变电脑端默认值或模型行为。每个浏览器都可以覆盖基于宽度的首次选择，并在重新加载后保留。偏好不会跟随用户前往另一台设备，工具专用展示保留自己的尺寸，激活后跨越断点也不会静默替换当前选择。
