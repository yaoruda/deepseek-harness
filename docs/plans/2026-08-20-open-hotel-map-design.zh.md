# 开放酒店地图设计

[English](2026-08-20-open-hotel-map-design.md) | 中文

## 目标

一个模型工具把酒店名称和地址转换为持久化地图结果。Web 客户端绘制全部已解析酒店；调用方提供一个目的地时，还会显示每家酒店到该地点的免费驾车和公共交通估计。公交覆盖缺失不会移除酒店标点或驾车结果。

第一版不搜索酒店库存、不报价、不展示空房，也不预订房间。

## 组件

Host 包拥有一个 `hotel_map` 工具及其持久化事件。工具接收一个目的地和有上限的酒店列表，通过配置的地理编码服务解析缺失坐标，通过配置的服务请求驾车和公交路线，并在全部工作结束后追加一条完整的 `travel-map/show` 事件。标准结果会标记每项输入已解析或未解析，并区分公交覆盖不可用和服务请求失败。

Web 客户端包把每条 `travel-map/show` 事件折叠为一个带 key 的 Chat node。它通过 MapLibre 渲染兼容 OpenStreetMap 的瓦片、带编号酒店标点、可选目的地标点、可选择的驾车或公交路线几何，以及紧凑结果列表。渲染器在重放时不执行网络 I/O；路线几何、时长、距离、服务署名和状态都是持久事件字段。

服务根 URL 是部署配置，而不是执行逻辑中的隐藏常量。默认配置面向低频社区服务：兼容 Nominatim 的地理编码、兼容 OSRM 的驾车路线和 Transitous MOTIS 公共交通路线。部署可以把每个接口指向自建服务，无需修改工具或 Skill。

## 数据流和限制

工具会在联网前清理并校验每个地址，拒绝空酒店列表，并按配置限制数量。地理编码按配置间隔串行执行，成功地址结果缓存在进程内。请求标识应用、携带取消和超时，并且不会把服务原始响应直接暴露给模型或客户端。

目的地缺少坐标时只编码一次。任一路线服务失败时，已经解析的酒店仍会保留。驾车和公交结果使用明确状态：`available`、`unavailable` 或 `failed`。`unavailable` 表示服务未返回可用路线；`failed` 表示请求没有成功结束。用户文案不会在只有服务失败时声称路线不存在。

Session 重放所需的全部地图数据作为一条有上限事件追加。事件记录署名文字和来源 URL，供客户端满足服务方和 OpenStreetMap 署名要求。它不持久化服务凭据或不受限的原始响应。

## 用户体验

node 初始显示全部标点。选择酒店会高亮它的标点和列表行。存在路线数据时，用户可以切换驾车和公交，并查看所选路线、时长和距离。窄屏上地图位于列表上方，宽屏上两者并排。键盘用户无需操作地图画布即可选择每家酒店。

无法解析的地址保留在单独列表并显示诊断。没有公交覆盖时显示中性不可用状态。服务完全故障时仍会得到可重放结果，其中包含原始酒店名称、地址和失败信息，而不是静默忽略地图请求。

## 验证

Host 单元测试覆盖 schema 限制、串行地理编码、缓存、取消、服务响应标准化、部分成功和事件追加时机。真实 Loader 组合测试使用本地 HTTP fixture 挂载插件，并验证模型可见结果和持久事件。

客户端测试重放完整事件，验证标点与列表选择、路线模式 fallback，并证明插件释放会移除 Definition 和 renderer。Web 快照或端到端 fixture 验证桌面和移动宽度下的组合 node。有上限的公开端点 smoke 测试用于验证当前集成，但不会把社区服务在线状态当作确定性仓库测试。

## 分发

功能以 opt-in Host、Client 插件和描述何时及如何调用 `hotel_map` 的 Skill 分发。Skill 不包含 API key。安装文档说明公共服务限制、署名要求、可配置端点和自建路径。
