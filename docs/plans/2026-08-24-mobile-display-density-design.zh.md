# 移动端显示密度设计

[English](2026-08-24-mobile-display-density-design.md) | 中文

## 结果

会话内容在手机宽度的浏览器中默认使用紧凑密度，同时保留现有电脑端展示。用户可以在通用设置中选择标准、紧凑或超紧凑；该选择仅应用于当前浏览器配置，并在重新加载后保留。

第一版调整会话文字、表格文字与单元格内边距、用户气泡内边距以及消息纵向间距。它不缩放应用外壳、地图、代码块、工具专用视图，也不会把输入框缩小到 16 px 以下。

## 归属与数据流

一个纯客户端显示密度插件负责偏好设置、浏览器存储、校验和文档的 `data-dsh-display-density` 属性。没有已保存偏好时，不超过 720 CSS 像素的视口解析为紧凑，更宽的视口解析为标准。选择密度时只向 `localStorage` 写入枚举值；它不存储 Session 或消息数据，也不通过服务器同步。

插件向 `settings.general.item` 提供一行设置。会话和 Markdown 渲染器使用显示密度 CSS 变量，不导入该插件，因此包之间保持单向关系。标准值保留现有尺寸。紧凑模式的助手和用户文字为 14/22 px，表格文字为 13/20 px，并收紧表格与气泡内边距以及会话间距。超紧凑模式的会话文字为 13/20 px，表格文字为 12/18 px。

所有模式下，输入框都保持 16/24 px，因为 iOS 会在聚焦的表单控件文字低于 16 CSS 像素时放大页面。viewport 元数据继续允许用户缩放。

## 失败处理

未知或格式错误的已存储值会被忽略，并由基于宽度的默认值替代。浏览器存储读取或写入失败时，内存中的选择在当前文档内仍然可用。插件资源释放时移除自己的 slot 配置项和文档属性，不影响其他功能的状态。

## 验证

单元测试覆盖基于宽度的默认值、有效与无效持久化、存储失败、文档投影、设置行操作和生命周期资源释放。一个 390 px 的无密钥完整浏览器场景验证紧凑模式为默认值，检查实际渲染的会话和表格尺寸，切换到标准模式并重新加载，然后确认当前设备的选择得到保留。现有电脑端表格和设置场景保护不变的宽屏展示。
